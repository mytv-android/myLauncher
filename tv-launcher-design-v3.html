01

关键决策与 v2 差异

v2 为了"稳"把 Google TV 最有辨识度的东西都禁掉了：背景跟随内容、玻璃层次、随内容变化的颜色。v3 把它们拿回来，用渲染分级保证低端盒子也能跑。功能与工程部分保留 v2 中验证过的结论，并按 2026-11 的一手资料修正了版本、权限和 API 细节。

视觉结构
采用 Google TV 2025 版主页骨架：左侧文字 Tab（主页 / 应用 / 小组件），右侧胶囊工具组（搜索 / 环境模式 / 快速设置），顶部精选轮播，下面是内容行。"你的应用"行用圆形图标（Google TV 自 2024-02 起如此），banner 留给应用页网格。背景始终显示焦点内容的画面。不设头像和账号：桌面没有云端账号，片单、隐藏项和布局都只存在本机。
视觉语言
按 Material 3 Expressive 落地：焦点和形状变化用 M3 弹簧 token（数值见 §03）；圆角用扩展刻度（含 20 / 32 / 48dp）；应用图标获得焦点时由圆形变为 9 边 Cookie 形；标题用 Emphasized 字重；Hero 使用按钮组，进度条使用 Wavy 样式。主题、动效和形状直接来自 material3 1.5.0-alpha25 的 MaterialExpressiveTheme、MotionScheme、MaterialShapes。
玻璃材质
使用 dev.chrisbanes.haze 2.0.1，API 为 hazeSource / hazeBlur / HazeBlurStyle。按三档渲染：T1 实时模糊，用于 API 31+ 且性能达标的设备；T2 冻结模糊，背景图变化时预先模糊一次，玻璃控件按自身坐标取样，覆盖 API 23–30 和视频背景；T3 纯色兜底。不启用 Haze 的实验性 RenderScript 路径，因为它在 Lazy 列表里有已知的不刷新问题。
动态取色
Android TV 上没有壁纸驱动的 Monet 动态色，配色由桌面自己生成。算法沿用 Material Color Utilities：Celebi 量化 → Score 选种子 → DynamicScheme，暗色，默认 TonalSpot 变体。取色来源可选焦点海报、应用图标、壁纸、视频关键帧或固定色。焦点停留 180ms 后切换全局主题，用效果弹簧过渡约 600ms；焦点光环立即使用该项自己的局部配色。取色结果预计算后缓存。
Material 3 版本
锁定 material3 1.5.0-alpha25。它是最后一个 minSdk 23 的 1.5.0 版本，从 alpha26 起要求 minSdk 24。alpha25 依赖 Compose 1.12.0-beta01，与 BOM 2026.09.00 的 1.12.1 同属一条版本线。在 alpha25 里，MaterialExpressiveTheme、MotionScheme、ButtonGroup、Wavy 进度条和 Emphasized 字体已经是正式 API；MaterialShapes 和 LoadingIndicator 仍需 opt-in。代价是在 minSdk 提到 24 之前，material3 不能再升级。详见 §15。
Channel
API 26+ 运行时申请 android.permission.READ_TV_LISTINGS，能读到所有 App 的 searchable=1（默认值）频道、预览节目和 Watch Next；查询不能带 selection，过滤在本地做。频道审批状态由桌面自己维护。API 23–25 可选用 NotificationListener 读取旧版推荐通知。OEM 版使用 ACCESS_ALL_EPG_DATA。Google TV 设备上新的"继续观看"走 Engage SDK，第三方读不到，界面必须能接受这一行为空。
小组件
第三方应用的小组件是核心功能：小组件页是网格画布，主页有一行速览；支持添加、移动、调整大小、重新配置，也可以用方向键进入小组件内部操作按钮。难点在绑定：绑定需要 BIND_APPWIDGET 或用户授权，而 AOSP TvSettings 没有授权确认界面。方案按顺序尝试五条路径：已获授权 → 系统确认界面（设备有就用）→ Shizuku 一键授权 → 一次性 ADB 命令 → oem 变体直接持有权限。同时接收 App 发起的"添加到主屏幕"请求（API 26+）。API 31+ 用 setColorResources() 让小组件跟随桌面配色，只在主题稳定后调用。内置 Compose 小组件作为补充。详见 §12。
系列应用
myBV、mydv、mytv-android 继续按标准 TvProvider 发布频道与 Watch Next，桌面原样读取，它们在其他桌面上的行为不变。第三方桌面做不到的上屏审批、移除回传、初始化，以及没有 TvProvider 的设备，用双向证书校验的系列直连补上（§11）。
环境模式
沿用 aerial-tv 的做法：主页空闲 10 秒后，航拍视频在磁贴后方播放。视频放在 SurfaceView 里，以保留 4K、HDR 和 DRM 能力。Haze 无法模糊 SurfaceView，所以按键返回时先用 PixelCopy 抓当前帧作为静态背景，再让玻璃效果生效；环境模式期间，配色跟随关键帧取色。

Material 3 Expressive 的电视化

M3E 来自 Google 的 46 项研究、超过 18,000 名参与者，结论之一是关键元素的识别速度最多可快 4 倍。它本身面向触屏；放到十英尺距离、用方向键操作时，能直接迁移的是动效、形状、字重和色彩，交互状态要改成以"焦点"为中心。

设计语言：Ambient Expressive

一句话：桌面自己不带颜色，颜色来自此刻焦点所指的内容；玻璃只承载界面框架，不承载内容。

五条原则

  1. 内容即环境。背景始终是焦点项的背景图、航拍或壁纸。
  2. 焦点即主题。全局配色跟随焦点停留结果；焦点光环用焦点项自己的局部配色，没有延迟。
  3. 玻璃只给框架。顶栏胶囊、快速设置、小组件外框、Toast 用玻璃；海报和应用图标本身是内容，不加玻璃。
  4. 弹性分层级。位移和缩放用 spatial 弹簧，可以回弹；颜色和透明度用 effects 弹簧，不回弹；长距离滚动用 Standard，不晃动。
  5. 十英尺可读。对比度由 HCT 色调差保证，原型中 onSurface 对 surface 约为 14:1；状态从不只靠颜色表达。

颜色从哪里来

  • Ambient 渐变：主色调色板 T12 从左侧压暗，surface（T6）从底部压暗。
  • 玻璃 tint：surfaceContainer 50% 透明度 + primary 6%。
  • 焦点光环：局部 primary T90（彩度上限 28）；光晕为 T62，60% 不透明度。
  • 主按钮 / 进度条：全局 primary T80，onPrimary T20。
  • 文字：onSurface N90，onSurfaceVariant NV80。

T 后的数字为 HCT 色调（等于 CIELAB 的 L*），N / NV 分别指中性与中性变体色调板。

// core:dynamiccolor —— 依赖 com.materialkolor:material-color-utilities（MCU 的 Kotlin 移植，包名以 6.0.0 为准）
class SeedExtractor(private val dao: SeedCacheDao, private val io: CoroutineDispatcher) {
  suspend fun seedFor(key: SourceKey, load: suspend () -> Bitmap?): SeedResult = withContext(io) {
    dao.get(key.value, ALGO_VERSION)?.let { return@withContext it.toResult() }
    val bmp = load() ?: return@withContext SeedResult.Unavailable
    val small = Bitmap.createScaledBitmap(bmp, key.sampleW, key.sampleH, true)
    val px = IntArray(small.width * small.height).also { small.getPixels(it, 0, small.width, 0, 0, small.width, small.height) }
    val opaque = px.filter { Color.alpha(it) >= 250 }.toIntArray()
    val quantized = QuantizerCelebi.quantize(opaque, 128)
    val ranked = Score.score(quantized, desired = 1, fallbackColorArgb = NO_SEED, filter = true)
    val result = if (ranked.first() == NO_SEED) SeedResult.LowChroma else SeedResult.Seed(ranked.first())
    dao.put(key.value, ALGO_VERSION, result); result
  }
}

// 全局主题：一个 Animatable 驱动插值，颜色在绘制阶段读取，过渡期间不触发重组
class ThemeController(private val scope: CoroutineScope) {
  private val progress = Animatable(1f)
  var from: LauncherColors = Defaults; private set
  var to: LauncherColors = Defaults; private set
  fun colors(): LauncherColors = lerp(from, to, progress.value)   // 在 drawBehind / graphicsLayer 中调用
  private var job: Job? = null
  fun onFocusSettled(seed: SeedResult, style: Variant) {
    if (seed !is SeedResult.Seed) return                         // 低彩度：保持当前主题
    val next = LauncherColors.from(SchemeFactory.dark(seed.argb, style, contrast = settings.contrast))
    if (deltaE(next.primary, to.primary) < 6f) return
    job?.cancel(); from = colors(); to = next
    job = scope.launch { progress.snapTo(0f); progress.animateTo(1f, LauncherMotion.ambientColor()) }
  }
}

规则

  • 整表读取，本地过滤：三张表各查一次，不带 selection，在内存中按频道分组。数据量通常是几百行，代价可以接受。
  • 审批状态自己存：新建频道的 browsable 默认是 0，第三方桌面又不能写这一列，所以"哪些频道显示在主页"记录在桌面自己的 ChannelApproval 表里。新频道出现时，在行末"管理频道"入口加角标，不弹窗打断。
  • 用户移除节目：PREVIEW_PROGRAM_BROWSABLE_DISABLED、WATCH_NEXT_PROGRAM_BROWSABLE_DISABLED 是受保护广播，第三方桌面发不出，移除只在本地生效；系列应用通过直连回传（见下文）。
  • App 请求显示频道：有两条路。requestChannelBrowsable()（publishDefaultChannel() 内部也会调用）由系统发出受保护广播 CHANNEL_BROWSABLE_REQUESTED，逐个发给声明了接收器的应用，带频道 id 和请求方包名；桌面注册接收器即可收到（TvInputManagerService 源码）。ACTION_REQUEST_CHANNEL_BROWSABLE 是 Activity Intent，桌面声明处理它的确认页，确认后写审批表并返回 RESULT_OK；系统桌面仍安装时由谁接收，需在 M0 验证。
  • 刷新：在 TvContract 的三个 URI 上注册 ContentObserver（只在前台注册），防抖 500ms，结果写入 Room；冷启动先显示缓存。
  • 启动安全：INTENT_URI 来自其他 App 写入的数据。解析后把 package 固定为该行的 package_name，清掉 URI 授权标志，捕获 ActivityNotFoundException。

class ChannelRepository(private val cr: ContentResolver, private val approvals: ChannelApprovalDao) {
  // 无 ACCESS_ALL_EPG_DATA 时，带 selection 的查询会抛 SecurityException：整表读取后在本地过滤
  suspend fun previewRows(): List<ChannelRow> = withContext(Dispatchers.IO) {
    val channels = cr.readAll(TvContractCompat.Channels.CONTENT_URI, Channel.PROJECTION, Channel::fromCursor)
      .filter { it.type == TvContractCompat.Channels.TYPE_PREVIEW }
    val programs = cr.readAll(TvContractCompat.PreviewPrograms.CONTENT_URI, PreviewProgram.PROJECTION, PreviewProgram::fromCursor)
      .groupBy { it.channelId }
    val approved = approvals.approvedKeys()                    // 桌面自己的审批表：包名 + internalProviderId
    channels.filter { ChannelKey(it) in approved }
      .map { ch -> ChannelRow(ch, programs[ch.id].orEmpty().sortedByDescending { it.weight }) }
  }
}

object SeriesBridge {
  const val ACTION = "com.github.mytv.action.LAUNCHER_BRIDGE"
  private val TRUSTED = mapOf(                                   // 包名 → 签名证书 SHA-256，构建时注入
    "com.github.mytv.bv" to Certs.MYBV, "dev.aaa1115910.bv" to Certs.MYBV,
    "com.github.mytv.dv" to Certs.MYDV, "com.github.mytv.android" to Certs.MYTV,
  )
  fun isSeries(ctx: Context, pkg: String) = TRUSTED[pkg]?.let { it == ctx.packageManager.certSha256(pkg) } == true

  fun sources(ctx: Context): List<ProviderInfo> =
    ctx.packageManager.queryIntentContentProviders(Intent(ACTION), 0)
      .map { it.providerInfo }.filter { isSeries(ctx, it.packageName) }

  fun call(ctx: Context, p: ProviderInfo, method: String, arg: String? = null): Bundle? =
    runCatching { ctx.contentResolver.call(Uri.parse("content://${p.authority}"), method, arg, null) }.getOrNull()
}

abstract class LauncherBridgeProvider : ContentProvider() {
  abstract fun onInit()
  abstract fun onApprove(channelKey: String, approved: Boolean)
  abstract fun onHide(programKey: String)
  abstract fun rows(table: String): List<ContentValues>          // 有 TvProvider 时返回空列表

  override fun call(method: String, arg: String?, extras: Bundle?): Bundle? {
    LauncherTrust.check(context!!, callingPackage)                  // 证书不符抛 SecurityException
    when (method) {
      "hello" -> return bundleOf("version" to 1)
      "init" -> onInit()
      "approve" -> onApprove(arg!!, extras?.getBoolean("approved", true) ?: true)
      "hide" -> onHide(arg!!)
    }
    return null
  }
  override fun query(uri: Uri, projection: Array<String>?, selection: String?, args: Array<String>?, sort: String?): Cursor {
    LauncherTrust.check(context!!, callingPackage)
    return rows(uri.lastPathSegment!!).toCursor(projection)
  }
  // insert / update / delete 一律抛 UnsupportedOperationException
}

class WidgetBinder(private val ctx: Context, private val host: AppWidgetHost, private val awm: AppWidgetManager) {
  sealed interface Bind { data class Ok(val id: Int) : Bind; data class NeedsGrant(val id: Int) : Bind }

  fun bind(info: AppWidgetProviderInfo, options: Bundle): Bind {
    val id = host.allocateAppWidgetId()
    return if (awm.bindAppWidgetIdIfAllowed(id, info.profile, info.provider, options)) Bind.Ok(id) else Bind.NeedsGrant(id)
  }

  // 路径 2：只有设备真的有处理者时才用
  fun systemBindIntent(id: Int, info: AppWidgetProviderInfo): Intent? =
    Intent(AppWidgetManager.ACTION_APPWIDGET_BIND)
      .putExtra(AppWidgetManager.EXTRA_APPWIDGET_ID, id)
      .putExtra(AppWidgetManager.EXTRA_APPWIDGET_PROVIDER, info.provider)
      .putExtra(AppWidgetManager.EXTRA_APPWIDGET_PROVIDER_PROFILE, info.profile)
      .takeIf { it.resolveActivity(ctx.packageManager) != null }
}

自己的视频

  • 上传：手机页把文件作为原始请求体发送（不用 multipart），服务端边收边写临时文件，不整段读入内存。写完后用 MediaExtractor 确认至少有一条视频轨，且 MediaCodecList 有对应的解码器；不满足时删除文件，手机页显示"无法播放这个视频"。

真机抓帧

aerial-tv（LiveWallpaper.kt）在真机上遇到两类问题：小米 MStar 机型上 PixelCopy 返回成功但画面全黑；TCL MT5879 上能抓到，但 4K 帧要 0.6–1.7 秒，期间主页卡住。本方案的处理：

  • 不在主线程等待：PixelCopy 的回调放在专用 HandlerThread；返回界面的动画不等结果，先显示上一张静态帧或预置关键帧，抓到后交叉淡入。
  • 150 ms 预算：任何一次成功的抓帧耗时超过 150 ms，本机此后不再使用 PixelCopy。
  • 全黑检测：结果按 16×9 网格采样，最大亮度低于 4% 视为全黑。当前片段的 keyColor 不是近黑色时，连续两次全黑即判定本机不可用。
  • 按固件记住：判定结果以 Build.FINGERPRINT 为键存入 DataStore，固件升级后重新探测；devices.json 可以预置结论（§16）。
  • 回退：航拍片单为每段影片预先提供关键帧图（按时间索引）和 keyColor，按播放位置取最近的一张。没有预置帧的片源（自己的视频）用 MediaMetadataRetriever.getFrameAtTime(t, OPTION_PREVIOUS_SYNC) 从本地文件取；航拍只从 1080p H.264 文件取，不碰 4K HEVC 与杜比视界文件。
  • 解析器卡死：部分固件的 MPEG4 解析器会在 MediaMetadataRetriever 里卡死（aerial-tv 在 TCL 上遇到）。取帧放在独立线程，10 秒超时；超时一次后，本次开机内不再从文件取帧，只用预置帧或壁纸。

解码器交接

电视通常只有一个 4K / HDR 解码实例。桌面的播放器占着它时，用户打开的应用可能起播失败。

  • 主动离开（打开应用或信号源，或在播放器暂停时启动屏保）：先抓帧（可用时），再释放暂停中的播放器（解码器与 Surface 一起释放），最后发出启动 Intent。环境模式正在播放时进入本应用屏保不在此列，见"从环境模式到屏保"。
  • 被动离开（其他应用或系统界面来到前台、待机）：播放器停在当前帧，最多再占用解码器 2.5 秒用于取得静态帧，到时无论成败都释放。
  • 回来：从记住的片段与位置重新起播。
  • 离开 HDMI 后延迟：devices.json 标记的机型（如 Mi TV 4，aerial-tv FilmAfterInput.kt 记录过整机重启）从信号源回到主页后，等 2.5 秒再打开解码器，期间显示静态帧或壁纸。

画质、缓存与失败处理

项规则
画质选项自动 / 1080p H.264 / 4K HEVC / 4K 杜比视界。"自动"按解码能力、HDR 能力和设备档位（§17）选可播放的最高一档。
运行中降级解码器初始化或解码失败（Media3 错误码 4001–4005）时，在本进程内降一档重新起播，不改用户设置；再失败继续降，最低到 1080p H.264。
缓存上限可用空间的 1/4，限定在 64 MB–3 GB；LRU 淘汰；边播边写入。
预取定时屏保开始前 8 秒，预取下一段开头 6 MB；环境模式中下一段开始前同样预取。只在非计费网络上进行。
失败阶梯连接 5 秒、读取 8 秒超时，重试一次；起播后 8 秒内没有画面则跳到下一段；连续 3 段失败后改用照片或壁纸，下次进入环境模式时再试影片。

从环境模式到屏保

  • 同一个播放器：环境模式正在播放时进入本应用的屏保（桌面内屏保或本应用的 DreamService，同一进程），把播放器的输出 Surface 切到屏保窗口，片段、位置和画质不变，不黑屏、不重新缓冲。只有用户为屏保单独选了更高画质（如 4K 杜比视界）时才重新起播，切换时可能黑屏一次。
  • 跨重启续播：当前片段 ID 与播放位置（毫秒）每 10 秒及离开时写入 DataStore；进程重启或开机后从这里继续。
  • 小集合轮换：航拍片单在本机只轮换 3 段，每天换入一段新的、移出最旧的一段，提高缓存命中；屏保中左右键切换上一段 / 下一段。

屏保兜底

  • 桌面内屏保：本应用的 DreamService 不是当前系统屏保（Settings.Secure 的 screensaver_components 不含本组件，或读取不到），或机型在 devices.json 中标记为不列出第三方屏保时启用。主页空闲达到设定时长（默认 10 分钟）后，桌面在自己的窗口里全屏播放；只在桌面位于前台时生效。
  • 不妨碍待机：桌面内屏保运行时设置 FLAG_KEEP_SCREEN_ON，累计达到系统关屏时长（Settings.System.SCREEN_OFF_TIMEOUT）后清除，交回系统按原设置待机。
  • 立即启动：快速设置的"屏保"项提供"立即启动"，直接进入本应用屏保（§14）。
  • 内容：航拍片单、自己的视频、照片（含必应每日一图）、时钟，与 DreamService 共用一套渲染；任意键退出，回到进入前的页面与焦点。

分发与更新

standard 变体以 APK 侧载发行（项目网站与 GitHub Releases），没有应用商店的更新通道，所以自带更新检查。oem 变体随系统 OTA 更新，不含 core:update。

步骤规则
检查启动后及每 3 小时读取一个小的版本文件（versionCode、versionName、最低 API、下载地址、大小、SHA-256）；失败按 30 秒 / 2 分钟 / 10 分钟 / 30 分钟退避，不提示。
更新说明取已安装版本之后的全部更新说明，按版本倒序合并，显示在桌面设置的"更新"项。有新版本时该项显示"有新版本 {版本号}"；主页不弹窗。
下载用户确认后下载到应用私有目录，支持断点续传，完成后校验大小与 SHA-256。
校验getPackageArchiveInfo() 读取下载的包：包名与本应用相同；签名证书与已安装版本相同（API 28+ 用 GET_SIGNING_CERTIFICATES，之前用 GET_SIGNATURES）；versionCode 大于已安装版本。任一不符即删除，不安装。
安装PackageInstaller 会话，APK 与对应的 .dm 写入同一会话。API 31+ 设置 setRequireUserAction(USER_ACTION_NOT_REQUIRED) 并声明 UPDATE_PACKAGES_WITHOUT_USER_ACTION：本应用是上一次的安装者时可以免确认；第一次从手动侧载的版本自更新，或系统不允许时，照常弹出安装确认。需要 REQUEST_INSTALL_PACKAGES，API 26+ 要用户允许"安装未知应用"。会话失败时，API 24+ 回退为 ACTION_VIEW + FileProvider 交给系统安装器（不带 .dm）。
Baseline Profile发行时为 APK 生成 .dm（dex metadata，API 28+ 生效）：API 28–30 与 API 31+ 各一份（profile 格式不同），安装时按设备 API 级别选择。
首次启动核对更新或侧载后首次启动，用 androidx.profileinstaller 的 ProfileVerifier 查看是否已按 profile 编译；结果只写入诊断日志，界面上不提示。
ADB 安装开发与测试中用 adb install 安装时没有 .dm。安装并启动一次后执行 adb shell cmd package compile -m speed-profile -f <pkg>，让 profile 立即生效。
旧系统证书API 23–24 的系统证书库没有 ISRG Root X1。更新、天气与图片请求的服务器若使用 Let's Encrypt 证书，这两级上要用应用内置的根证书（API 24 用 network_security_config，API 23 用自定义 TrustManager）。
签名密钥发行签名密钥离线保存并备份；密钥一旦更换，已安装用户无法通过应用内更新升级（§20）。

ADR

ADR-001
不使用 androidx.tv 组件库；随焦点变化的组件自建，material3 提供主题、动效、形状和不可聚焦的组件。原因：tv-material 无 Expressive 支持，与手机版 Material 混用有已知问题；M3 的 ButtonGroup 等交互动画由按下驱动，不由焦点驱动。
ADR-002
material3 锁定 1.5.0-alpha25，直接使用 MaterialExpressiveTheme、MotionScheme、MaterialShapes。原因：它是最后一个 minSdk 23 的 1.5.0 版本，Expressive 的主题与动效 API 已是正式版。
ADR-003
玻璃采用 Haze 2 三档渲染，不启用 RenderScript 路径。原因：该路径在 Lazy 列表中有不刷新的问题，且官方标为实验性。
ADR-004
动态取色完全由桌面实现，不依赖系统 Monet；低彩度来源保持当前主题。原因：TV 版 SystemUI 不做壁纸取色；回退到默认蓝色会造成整屏跳色。
ADR-005
视频始终使用 SurfaceView；玻璃通过抓帧 + T2 适配视频背景。原因：TextureView 会失去 DRM 安全输出、HDR 与全分辨率。
ADR-006
Channel 数据只读，主页显示哪些频道由桌面自己的审批表决定。原因：第三方无法写 browsable，也无法发送相关受保护广播。
ADR-007
第三方 AppWidget 是核心功能，绑定授权按五条路径依次尝试，内置 Compose 小组件作为补充。原因：AOSP TV 开启了 AppWidgetService，但 TvSettings 不提供绑定确认界面；shell 用户持有授权所需权限，授权一次即可持久生效。
ADR-008
系列应用继续用标准 TvProvider 发布，桌面原样读取；上屏审批、移除回传、初始化和没有 TvProvider 的设备，由双向证书校验的直连补上。原因：保证它们在其他桌面上行为不变，同时补齐第三方桌面缺少的系统权限。
ADR-009
儿童模式与长辈模式在 standard 变体中不用无障碍服务，只靠桌面自身、亮屏状态、使用情况访问和默认桌面的后台启动豁免；做不到的部分在设置页如实显示，系统级强制留给 oem。原因：standard 不接管系统按键、不做守护（§04）；执行强度取决于 M0 结论与可选的 ADB 授权。
ADR-010
standard 变体自带更新通道，用 PackageInstaller 会话安装，并在会话中附带 .dm。原因：侧载发行没有商店的更新与云端 profile；不带 .dm 时 Baseline Profile 要等系统空闲时编译，电视上可能长期不生效。

## 12 项验证结论

1. **Haze T1 帧时间**：T1 能在 API 31+ 运行，但五台模拟器均未达到 60fps（api31g P50 50.01ms、api34g 83.34ms、api36 166.67ms；T3 基线也受模拟器渲染限制）。五台 AVD 共用同一个 x86 宿主，不能满足“3 种 SoC”的设计要求，真机必须复测后才能决定 T1 档位。证据：`docs/m0/evidence/item01-haze.json`。
2. **T2 冻结玻璃**：按坐标取样的冻结位图在五台设备上对齐偏移均为 0px；生成 54.9–2005ms，换背景 29.5–1431ms。T2 纯 Kotlin 实现，API 23 可用。证据：`docs/m0/evidence/item02-frozen.json`。
3. **PixelCopy**：API 28+ 的 SurfaceView 抓帧成功（61–492ms，画面非全黑）；Window 级抓帧在四台设备上全黑；API 23 不支持；DRM 受保护内容无法在模拟器上测。证据：`docs/m0/evidence/item03-pixelcopy.json`。
4. **READ_TV_LISTINGS**：API 28+ 能读到 3 个频道、10 个预览节目、3 个 Watch Next 行；带 selection 的查询全部抛 SecurityException。API 23 有 TvProvider authority 但没有 preview/watch-next 表。证据：`docs/m0/evidence/item04-tv-listings.md`。
5. **REQUEST_CHANNEL_BROWSABLE**：系统桌面仍安装时，AOSP ATV 由 `tvrecommendations/.AddChannelActivity` 接收，Google TV 由 `launcherx/...AddChannelActivity` 接收；API 23 无处理者。桌面必须自己声明处理 Activity。证据：`docs/m0/evidence/item05-browsable.md`。
6. **小组件**：五台设备都没有 `ACTION_APPWIDGET_BIND` 处理者，但 `appwidget grantbind` 后第三方宿主可直接绑定（P03 全部通过）；探针在 api31g 成功绑定并收到 onUpdate。Shizuku 与常见手机小组件的电视布局未测。证据：`docs/m0/evidence/item06-widgets.md`。
7. **material3 1.5.0-alpha25**：主空壳与 spike 在 API 23/28/31/34/36 上均可运行 `MaterialExpressiveTheme` + `MotionScheme`；冷启动 875–7313ms（模拟器参考值）。MaterialKolor 5.0.1（minSdk 21）会引入 JetBrains Compose material3 1.10.0-alpha05，与锁定版本冲突；按 PLAN 直接使用 MCU 6.0.0（minSdk 21，仅 stdlib/poko）。证据：`docs/m0/evidence/item07-material3.md`。
8. **系列应用直连**：夹具 series 的 LAUNCHER_BRIDGE 协议与证书固定通过（K08）；真实 myBV 1.0.0.r1119、myDV 2.1.1、mytv-android 3.0.0.2806 的 APK 都没有 LAUNCHER_BRIDGE Provider，无法端到端联调。按 AGENTS.md 不修改这三个应用，需在系列应用侧补 Provider。证据：`docs/m0/evidence/item08-series.md`。
9. **儿童模式执行手段**：Android 6/9 后台拉起锁屏无需豁免；Android 12/14/16 无豁免被阻止，授予 `SYSTEM_ALERT_WINDOW` appop 后成功；HOME 角色/默认桌面在 Google TV 上不生效，不能作为豁免来源。证据：`docs/m0/evidence/item09-kids.md`。
10. **HOME 兼容**：五台模拟器上 `cmd package set-home-activity` 都返回 Success 但不改变实际 HOME；API 28 无 `cmd role`，API 31/34/36 的 `add-role-holder` 也不改变 HOME 键行为；api28 停用系统桌面后 `set-home-activity` 才生效。该事实会让验收工具在 M1 准备阶段失败，见 ADR-001 与 `docs/acceptance-issues.md` A-001。证据：`docs/m0/evidence/item10-home.md`。
11. **IP 推测服务条款**：ipinfo.io 现在必须带 token；免费 Lite 只有国家级数据，城市级要付费 Core；无 token 的 `https://ipinfo.io/json` 实测 HTTP 429；AUP 禁止未授权自动化访问。设计稿的“无密钥免费城市级 IP 推测”无法成立，见 ADR-002。证据：`docs/m0/evidence/item11-ipinfo.md`。
12. **文件与安装入口**：所有文件访问页在 API 34/36 存在，API 23/28/31 没有；安装未知应用页从 API 26 起存在；DocumentsUI 在电视镜像上不可用，目录授权无法用遥控器完成；PackageInstaller 确认界面在五台设备上都可用遥控器完成安装与取消；api34g 的可移除 vfat 卷只有 all-files 授权后才能写，其他设备没有可移除卷。证据：`docs/m0/evidence/item12-files-install.md`。

## 已知问题与限制

- **Haze T1 的 SoC 数据缺失**：五台 AVD 都跑在同一宿主上，不能替代 3 种真实 SoC；T1/T2/T3 的最终档位必须在目标硬件上复测。模拟器上的帧时间只用于确认功能可运行。
- **PixelCopy DRM 未测**：模拟器没有 Widevine 受保护内容；API 24/26 也不在矩阵内。受保护内容黑帧、耗时与 `devices.json` 预置结论留到真机。
- **Shizuku 路径未测**：本机没有安装 Shizuku；`opt:shizuku` 的端到端授权留到 M3/真机。常见手机小组件的触屏布局与焦点表现也没有素材。
- **真实系列应用缺少直连 Provider**：myBV/mydv/mytv-android 当前构建都没有 `LAUNCHER_BRIDGE`；M3 之前需要系列应用侧补上。
- **无法设置第三方默认桌面**：矩阵 AVD 的系统桌面被钉住，验收工具 `set_home` 会失败；已写 ADR-001 与 `docs/acceptance-issues.md` A-001，等待用户裁决。
- **ipinfo.io 无法免费城市级推测**：已写 ADR-002，等待用户裁决；在裁决前 M3 不实现 IP 推测。
- **DocumentsUI 与 U 盘**：电视镜像没有可用的 DocumentsUI 入口；只有 api34g 有可移除 vfat 卷，作为 U 盘近似。真实 U 盘、SD 卡与国产固件入口按 PLAN 4.1 留给真机。
- **模拟器性能值**：api28 与 api36 的 T3/冻结模糊耗时明显高于其他镜像，属于模拟器负载差异，不能当作真机预算。

## 设计稿未写明、按实现需要补充的细节

- **compileSdk 37**：设计稿锁定 targetSdk 36；Compose 1.12.1 的 AAR 元数据要求 compileSdk ≥ 37，因此 compileSdk 用 37，targetSdk 保持 36。minSdk 23 不变。
- **Gradle 9.8.0 + AGP 9.4.1 内置 Kotlin**：AGP 9 起内置 Kotlin 支持，不能再应用 `org.jetbrains.kotlin.android`；Compose 编译器插件仍用 `org.jetbrains.kotlin.plugin.compose` 2.4.20。构建脚本按 AGP 9 的 DSL 编写。
- **M0 空壳提前声明 HOME 兼容属性**：S09 在 M0 就检查 HOME 的 COMMON_HOME/HOME.CC/TCL meta-data 与 `launchMode` 等属性；因此这些声明在 M0 空壳里已存在（PLAN 把 HOME 兼容清单写在 M1）。
- **debug 状态接口的初始值**：M0 只返回 `{"contract":1,...}` 的完整字段骨架，`page=home`、`mode=browse`，未实现的功能给 null/空值；不维护第二份状态。
- **spikes 独立构建**：`spikes/` 有自己的 `settings.gradle.kts`，不进入主工程 `settings.gradle.kts`；复用根目录的 Gradle Wrapper，通过 `gradlew -p spikes` 构建。
- **M0 报告的设备事实**：`docs/m0/m0-results.json` 是 M0 的证据文件，不是运行时数据；它与 P01–P04 的探针结果逐项一致。

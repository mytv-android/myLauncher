01

执行摘要与关键决策

默认体验是“内容优先、启动可靠、无商业推荐”。首页采用实体表面、续看主卡和横向内容行；应用与小组件始终是独立主目标。航拍仅属于可选屏保与环境模式，不再作为首页视觉背景，更不能阻塞应用启动。

23–36SDK 覆盖范围；所有高版本能力运行时门控
3 个主导航推荐 / 应用 / 小组件，搜索与控制中心为辅助入口
2 个发行轨道标准安装版与 OEM 系统版共享 UI 和领域层
0 个 androidx.tv 依赖仅使用标准 Compose 与 Material 3 手机版组件
界面技术
标准 Jetpack Compose + androidx.compose.material3:material3。使用 Material 3 的 Card、Button、Chip、Tab、Dialog、Switch、Slider 等手机版/通用控件；不引入 androidx.tv:tv-material、androidx.tv:tv-foundation。D-pad 适配由项目内 core:tvinteraction 完成。
视觉路径
Google TV 负责“顶部文字导航、续看主卡、横向内容行、海报与来源归属”；M3 Expressive 负责组件状态、色彩、形状和弹性反馈。明确禁用玻璃拟态、悬浮应用坞、首页全屏视频背景、问候语首屏和全导航胶囊化。不是复制 Google TV 皮肤，也不把移动端规范原样放大。
Channel 策略
系统推荐 Channel 仅在 API 26+ 尝试接入。普通版采用“系统可见数据 + 授权合作方数据”；OEM 版通过系统集成（系统签名或 priv-app 授权路径，按 ROM 配置白名单）获得全量读取。API 23–25 不伪装支持系统 Channel，只显示本地或合作方内容。
小组件策略
使用公开 AppWidgetHost / AppWidgetHostView，经系统绑定授权与可选配置 Activity。Compose 只负责外层页面和 M3 边框，真实 Widget 用 AndroidView 承载。
性能策略
缓存首页先行，网络和图片后补；首页固定使用静态中性表面，视频仅用于独立环境模式与屏保。低配置模式减少阴影、并发图片和活动 Widget 数，而不是降低焦点反馈。
分发策略
标准版只使用公开 API，不以隐藏 API、Root 或隐蔽保活作为前提。厂商接管、开机直达、全量频道、直接亮度控制等能力进入 OEM 适配层。
先过技术闸门，再承诺 UI

第一项开发任务不是画首页，而是在目标 ROM 上验证：默认 HOME、TvProvider 实际可见行、Widget 绑定/配置、D-pad 操作 RemoteViews、HDMI 切换、视频解码。任何一项未通过，都按本文定义的降级路径呈现。

02

参考项目拆解：借鉴什么，不复制什么

调研基于 2026-11-02 的 aerial-tv main 分支公开源码。仓库当时使用 Kotlin、标准 Compose、Media3、NanoHTTPD 与 ZXing，应用模块 minSdk 21、compileSdk 36。本方案只借鉴其能力分层和工程思路，不复用其品牌与界面。

aerial-tv 已确认的能力值得借鉴的工程思路本方案的处理
应用网格、文件夹、隐藏、改名、自定义图标、排序首页布局独立于应用列表持久化；包变更后增量刷新P0 保留，改为 M3 Expressive 网格与焦点反馈
HDMI / 信号源固定到首页，部分品牌专门适配通用 TvInputManager + 厂商适配，不假设所有 ROM 行为一致P0 基础入口，品牌适配按实机逐项验收
航拍壁纸、系统 DreamService 屏保、本地照片与视频首页与屏保共享媒体缓存；Media3 缓冲、重试、解码能力探测P1 独立环境模式 / 屏保，不进入推荐首页背景，媒体需自有或已授权
二维码手机整理页面电视提供局域网配置入口，手机负责复杂拖拽和文字输入P1 可选，缩短 Token 有效期、服务按需启动、增加速率与上传限制
标准版与 guard 版；无障碍、通知监听、用量统计等桌面守护把国产 ROM 差异隔离在设备适配层不作为默认核心；优先默认 HOME，守护需单独合规评审和明确授权
低配置“流畅”效果、Baseline Profile、R8、首屏分段加载性能是功能，不是最后优化P0 保留，建立设备等级与可观测预算

可以直接借鉴

  • 首页先显示缓存，应用列表与媒体异步补齐
  • 长按 OK 进入整理，而不是把所有设置堆在首屏
  • 应用、文件夹、信号源统一为可排序 HomeItem
  • 视频缓存按能力、清晰度与可用空间设上限
  • 针对国产 ROM 做能力探测与适配白名单

需要重新设计

  • aerial-tv 当前没有 Channel / AppWidget 宿主模型，本方案新增完整数据层。
  • 手机配置服务不能只靠长期有效的 URL Token；本方案改为按需服务和短期配对。
  • Apple 航拍影片版权归 Apple，不能因公开可访问就默认可商用分发或长期热链。
  • 桌面守护不等于标准 Launcher 必需能力，不能用权限堆叠掩盖系统限制。

已核实 参考仓库声明主代码 MIT、Inter 字体 OFL；引用源码仍需保留相应许可。本方案是独立设计文档，不包含其源代码。

03

产品定位、用户与范围

目标设备是 Android TV、Google TV、电视盒子与投影；兼容国产 Android 固件，但不承诺所有厂商都允许第三方桌面接管。webOS、Tizen 和非 Android 系统不在范围内。

核心用户

效率型家庭用户

希望按 HOME 就看到常用 App 和 HDMI，不被运营内容打断；要求少按键、字大、焦点明确。

增长用户

内容续看用户

希望从不同视频 App 回到观看进度。是否能聚合取决于 ROM 权限与内容方授权，而非 UI 开关。

进阶用户

桌面整理爱好者

需要文件夹、图标、排序、小组件、环境屏保和手机整理，同时接受部分第三方 Widget 对遥控器支持有限。

设计原则

  1. 两步内启动：首页任何常用 App、HDMI 或续看内容最多两次方向键加 OK 到达。
  2. 启动路径零网络依赖：断网时本地应用、文件夹和已绑定 Widget 仍可操作。
  3. 焦点永远有答案：看得见、移得回、不会消失；加载与空状态也不能造成焦点丢失。
  4. 内容来源透明：每个频道和节目显示来源 App，不将合作方内容伪装成桌面自有内容。
  5. 能力缺失可解释：用简短空状态说明系统版本、权限或来源限制，不显示永久转圈。

非目标

  • 不做电视直播 EPG、播放器或 TvInputService。
  • 不绕过系统签名、用户授权或 Widget 配置流程。
  • 不在标准版承诺“与 Google TV 首页完全相同的频道数据”。
  • 不以广告推荐、桌面竞价排名或隐蔽保活作为商业/技术前提。
  • 不强制云端账号；布局默认保存在本机。

功能优先级

级别功能完成定义
P0HOME、应用/文件夹、排序、静态主题背景、D-pad、设置、缓存与低配置模式Android 6 真机可安装为默认桌面，断网完成核心操作
P0Widget 选择、绑定、配置、摆放、移除与生命周期测试 Widget 全流程通过；失败有可恢复状态

P2语音、云备份、多用户、儿童空间、主题商店单独立项，不进入首版关键路径
04

信息架构与首屏布局

采用 Google TV 的内容浏览骨架，而不是 tvOS 的应用坞。顶部是文字 Tab，下面是续看主卡与内容行；背景始终为静态中性色，所有标题、来源和操作都有固定位置。

继续观看 · 来源 App内容主卡
常用应用
观看下一步
结构线框：文字导航 / 续看主卡 / App 行 / 内容行。无玻璃层、无悬浮 Dock、无背景视频。

首页行的默认顺序

  1. 续看主卡：只展示一项明确的继续观看或来源精选，含标题、来源、进度与主操作；无内容时整块移除。
  2. 常用应用：7–10 个，图标与名称始终可见，不做悬浮底板。
  3. 观看下一步：横向 16:9 卡片，标题和来源位于海报下方，进度位于海报底边。
  4. 内容频道：每行一个来源，默认展示一行，其余由用户开启。
  5. 小组件速览：可选且位于内容之后；完整画布在独立 Tab。

方案自定 无任何合法内容来源时，首屏直接以常用应用开始，不展示伪造推荐、问候语或巨大空状态。

05

Material 3 Expressive 电视视觉系统

新版明确放弃 tvOS 的玻璃、悬浮与全屏氛围背景。M3 Expressive 用于组件状态、强调色、形状变化和弹性反馈，Google TV 用于内容结构。以下 dp、sp、时长、断点均为本方案 token，不冒充官方 TV 数值。

实现约束已锁定

使用标准 MaterialTheme 与 Material 3 手机版组件，以项目锁定稳定版本中可用的 Expressive API 为准；不依赖 MaterialExpressiveTheme 或 MotionScheme 等未经版本确认的 API 名称。自定义 LauncherTheme 注入色彩、字体、形状和动效 token。

不再使用

  • 全屏航拍或视频作为首页背景
  • 半透明玻璃、背景模糊、悬浮 Dock
  • “晚上好”等无信息问候语占据主区域
  • 大圆角图标阵列、光晕和聚焦后才显示标题
  • 整组导航都做成胶囊

新的视觉依据

  • Surface / Surface Container 建立稳定层级
  • 主卡、App 行、内容行拥有不同信息密度
  • Primary 只用于当前 Tab、焦点和主操作
  • 海报是内容，不作为整个页面的皮肤
  • M3 按钮、Chip、Card 的状态变化承担 Expressive

5.1 色彩：中性表面，有限强调

  • 首页 Background 固定为中性深色，不随海报或壁纸整屏换色；内容卡使用 Surface Container 分区。
  • 海报取色只允许进入主卡的局部 artwork，不扩散为光晕、模糊或整屏渐变。
  • Primary 同时用于当前 Tab、焦点描边和主按钮，建立统一操作语义；Secondary/Tertiary 只用于少量状态标签。
  • 正文与背景目标对比度至少 4.5:1，大字至少 3:1；焦点同时有形状和描边，不能只靠颜色。
  • API 31+ 可选用系统动态色，但只能映射到 Surface 与按钮角色；API 23–30 使用内置配色。

06

手机版控件的电视化：遥控器、焦点与滚动

这是“不用 Compose for TV”后最重要的工程模块。Material 3 手机版控件保留其视觉、语义和状态，但焦点导航、按键、自动滚动与恢复必须显式实现。

6.1 自建 core:tvinteraction

  • TvFocusableCard：Material 3 Card + InteractionSource 焦点状态 + 外描边 + 语义。
  • TvFocusRow：标准 LazyRow + 每行独立 FocusRequester + BringIntoViewRequester。
  • TvFocusGrid：标准 LazyVerticalGrid + 固定列映射与跨区最近邻规则。
  • TvKeyEvents：统一 DPAD、OK、BACK、MENU、长按和连发节流。
  • TvFocusMemory：按页面与行保存逻辑 item key，进程恢复后找最近有效项。
  • TvDialog：Material 3 AlertDialog 外层建立 focusGroup，默认焦点在安全的非破坏操作。
@Composable
fun TvFocusableCard(
  onClick: () -> Unit,
  modifier: Modifier = Modifier,
  content: @Composable () -> Unit
) {
  val interactionSource = remember { MutableInteractionSource() }
  val focused by interactionSource.collectIsFocusedAsState()
  Card(
    onClick = onClick,
    interactionSource = interactionSource,
    modifier = modifier
      .onFocusChanged { /* 上报焦点、请求 bringIntoView */ }
      .tvFocusRing(focused),
    shape = tvCardShape(focused),
    colors = CardDefaults.cardColors()
  ) { content() }
}

示意代码只表达职责，不要求逐字采用；具体 Card 参数与实验性 API 以锁定 Compose 版本为准。不要把 focusable() 无差别叠加到已可点击控件上，以免产生两个焦点节点。

6.2 按键契约

6.3 焦点算法与异常恢复

  1. 逻辑坐标优先：规则网格按列索引；频道行按可见中心 X；Widget 画布按矩形中心距离加方向惩罚。
  2. 只导航到可见且可用项：过滤 disabled、隐藏、移除中和被 Dialog 遮罩的节点。
  3. 滚动先于焦点丢失：目标取得焦点前后都请求 bringIntoView，目标位置预留焦点放大与标题空间。
  4. 数据变化找稳定 key：App 使用 ComponentName，Channel 使用 namespaced ID，Widget 使用 appWidgetId，不使用 Lazy 列表位置作为永久身份。
  5. 原项消失：同行下一项 → 上一项 → 行标题 → 首页默认项；同时记录诊断事件。
  6. 进程死亡：只恢复页面、行与 item key，不恢复临时 Dialog、绑定授权或半完成拖拽。
手机版控件不会自动成为优秀电视控件

必须为 Card、Tab、Chip、Switch、Slider、Dialog、LazyRow/LazyColumn/LazyVerticalGrid 做真机 D-pad 测试。Slider 使用左右键步进、OK 进入调节、BACK 退出；Switch 整行可聚焦，不能只有小滑块能操作。

07

核心页面与状态设计

7.1 推荐首页

首页为固定中性背景，顶部使用 TopAppBar + 文字 Tab、搜索、设置与时钟。续看主卡左侧显示来源、标题、进度和 M3 主按钮，右侧为局部 artwork；应用行使用 56–64dp 图标并始终显示名称；内容卡使用 16:9 海报，标题与来源置于海报下方。每行末尾有“管理”，长按不是唯一入口。

7.2 全部应用与整理模式

  • 网格支持 4 / 5 / 6 / 7 列（依宽度 dp 自动限制），搜索过滤时保持固定列与焦点。
  • 长按 OK 打开 M3 菜单：移动、加入文件夹、重命名、替换图标、隐藏、应用信息、卸载。
  • 移动模式用焦点描边变为表达色，并显示“方向键移动 · OK 放下 · 返回取消”；事务未完成不写入最终顺序。
  • 卸载调用系统确认；系统应用只提供“停用/隐藏”可用入口，不伪装已卸载。
  • 包安装、更新、卸载通过广播与 PackageManager 重新对账，更新期间保留用户布局。

7.3 小组件画布

采用独立页面而非把所有 Widget 塞进首页。默认 8 × 4 逻辑网格，Widget 依据 minWidth/minHeight 与 resizeMode 换算占位；外框显示来源、尺寸和焦点。OK 进入内部交互，BACK 返回外框，长按打开移动/缩放/移除。手机版 Widget 不一定支持 D-pad，无法操作时明确提示“该小组件可能需要鼠标或触摸”，不拦截系统外接输入设备。

7.4 频道与内容详情

频道头显示来源 App、频道名和可见状态。海报卡 OK 直接触发来源提供的 Intent；长按提供“打开来源应用 / 在本桌面隐藏 / 内容信息”。详情面板不是第二个播放器，只补充描述、时长、进度与打开按钮。失效链接显示可返回的错误，不让 Launcher 崩溃。

7.5 控制中心与设置

从顶部右侧或 MENU 进入右侧 M3 面板：信号源、网络、音量、可用时的亮度、环境与屏保、个性化、系统设置。普通版无法直接修改的设置跳转系统页面。危险操作如清空布局、解绑全部 Widget 使用二次确认，默认焦点为“取消”。

7.6 必须设计的非理想状态

状态呈现焦点策略
首次启动选择常用 App、动效等级、是否启用内容来源；屏保与环境模式稍后发现，不强迫一次授予全部权限主按钮“完成”，可跳过 Channel/Widget
无网络保留缓存海报和静态背景；状态栏离线，不重试弹窗本地 App 不受影响
无频道权限 / 无来源隐藏聚合行，在频道管理内解释原因与可用操作焦点跳过整行
Widget 加载失败保留占位、来源和“重试 / 移除”占位仍可操作，不空白
低内存 / 低存储关闭环境媒体、停止预取、提示清理媒体缓存；首页实体表面不变不自动删除布局或 Widget 绑定
内容图片失败来源色实体占位 + 标题，不显示破图内容仍可打开
08

Android TV Channel：可落地的三种接入模式

“接收 Channel 推送”必须拆成系统推荐频道、合作方主动同步和直播 EPG。前两者进入首页内容行；直播 EPG 不属于本方案的推荐数据源。

AOSP 权限事实

TvProvider 的全量 EPG 数据访问权限是 com.android.providers.tv.permission.ACCESS_ALL_EPG_DATA，在 AOSP 清单中为 signature|privileged。普通调用方的 SQL 会被按包名过滤；持 READ_TV_LISTINGS 的查询可见范围仍受“自有 + 可搜索”等条件限制。不同 ROM 必须实测，不能把“声明权限”当成“获得全量数据”。

8.1 三种来源，不在 UI 上混为一谈

模式适用版本 / 分发数据范围实现承诺
System VisibleAPI 26+ 标准版ROM 实际允许读取的推荐 Channel / Program，可能只有部分运行时能力探测；必要时申请 READ_TV_LISTINGS；空 selection 查询并本地过滤尽力展示，不声称完整镜像

API 23–25：隐藏“系统 Channel”入口，Partner Bridge 和本地频道仍可用。推荐 Channel 是 Android 8.0 / API 26 起的机制，tvprovider 兼容库可以让代码在低版本编译，但不会给 Android 6/7 创造出系统推荐 Provider。

  1. 冷启动先读 Room 缓存，绝不等待 TvProvider 或网络。

8.3 Partner Bridge：标准版的开放补充

注册与推送

  1. 来源 App 调用 registerSource(packageInfo, capabilities)；Launcher 弹出用户授权，记录 UID、包名、证书摘要与配额。
  2. 注册成功后返回来源级会话 Token。后续 upsertChannel / upsertPrograms / removePrograms / publishWatchNext 同时校验 Binder 调用 UID 与 Token。
  3. 只接受显式版本号和结构化数据；Bitmap 不走 Binder，海报通过 HTTPS 或有读授权的 content Uri 传递。
  4. 不接受任意隐式广播作为推送通道，避免伪造来源；Token 可撤销，卸载与签名变化立即失效。

建议初始配额（可通过能力协商调整）

  • 每来源最多 3 个频道、每频道 50 个 Program、每次同步 100 条；单来源每分钟 20 次变更。
  • 必须提供稳定 externalId、标题、来源包名和 Intent；expiresAt 到期后由 Launcher 隐藏。
  • 连续 schema 错误或 Uri 异常进入退避，不影响其他来源；所有拒绝只记录必要诊断，不记录内容隐私。

8.4 Watch Next 与内容操作

  • Watch Next 在 OEM 聚合模式中按最后互动时间、来源与类型排序；同一内容以来源包名 + externalId 去重，不跨来源猜测合并。
  • “在本桌面隐藏”只修改 Launcher 本地可见性；“不再感兴趣”只有在系统或来源提供对应契约时才回传，不能静默删除他人 Provider 数据。
  • 点击频道 Logo 使用 appLinkIntentUri，点击节目使用 intentUri；失败时提供“打开来源应用”备选。
  • 普通合作方内容必须标注来源；商业合作排序若未来出现，必须单独标识，首版无商业排序。

8.5 明确排除：直播电视 Channel

TvContract.Channels 同时承载直播 EPG 的概念不等于它们都应进入推荐流。直播频道、节目时间表、 parental rating 与 TvInputService 属于另一条产品链路。本方案只用 TvInputManager 发现并启动 HDMI/输入源，不把直播 EPG 当内容推荐抓取。

9.2 宿主生命周期

  • 整个进程一个 AppWidgetHost 与固定 hostId；主线程创建，Activity onStart 调 startListening()，onStop 调 stopListening()。
  • Room 只保存 appWidgetId、provider、位置、尺寸和选项；RemoteViews 不可持久化，重启后由系统重新下发。
  • Compose 使用稳定 key 的 AndroidView 创建 AppWidgetHostView，重组时更新尺寸，不重复 allocate/bind。
  • 移除、绑定拒绝、配置取消、Provider 卸载均回收对应 ID；不能因清空 UI 忘记 deleteAppWidgetId()。
  • 从后台返回时对账 getAppWidgetInfo(id)；为 null 显示“来源不可用”占位，而不是直接丢弃用户位置。

9.3 尺寸与缩放

项目规则
初始跨度依据 minWidth/minHeight 与可用网格求最小可容纳跨度；旧式 70×n−30 公式只作估算，最终以实际布局测试为准。
resizeMode仅允许声明方向的缩放；不支持 resize 的 Widget 锁定跨度。
尺寸 Options尺寸变化后调用 updateAppWidgetOptions，写入实际 min/max width/height；高版本额外字段按 SDK 门控。
预览API 23–30 使用 previewImage / 图标；API 31+ 可使用 previewLayout、targetCellWidth/Height 等可用信息。
外框M3 焦点环和“移动/缩放”UI 在 RemoteViews 外部，避免第三方视图遮挡 Launcher 操作。

9.4 D-pad 与 RemoteViews 的边界

  1. 外框是主焦点；OK 后将焦点交给 AppWidgetHostView 内第一个可聚焦节点。
  2. 内部方向键优先由 RemoteViews 处理；到边界或无可用焦点时返回外框，但必须保留明确退出路径。
  3. 集合 Widget、时钟和简单按钮通常更可控；依赖触摸滑动、复杂 WebView 或自定义触摸的 Widget 不保证可操作。
  4. 不对 RemoteViews 强行改色、改字体或注入 M3 样式；M3 只负责外部容器。
  5. 首页最多放 2 个低刷新速览 Widget，完整画布限制活动实例数；更新频率仍由 Provider 与系统决定。
验收不能说“支持所有小组件”

准确承诺是“支持系统 AppWidget 宿主协议”。需建立天气、时钟、音乐、集合列表、带配置 Activity、无预览、无法绑定、Provider 崩溃等测试样本，并公开不兼容提示。

10

环境媒体与屏保

aerial-tv 的 Media3 播放与共享缓存只作为技术参考。推荐、应用和小组件界面不使用视频或照片作为全屏皮肤；媒体能力被限制在独立环境模式与系统屏保中。

Launcher 实体表面

首页、应用和 Widget 页面只使用主题 Background 与 Surface Container。无需解码壁纸，不随内容换肤，确保内容层级和低端设备启动稳定。

独立环境模式

由用户从控制中心主动开启的全屏媒体页，可显示已授权航拍、照片或简洁时钟。没有导航和海报悬浮其上，BACK 立即返回原焦点。

DreamService 屏保

按系统屏保入口启动，与环境模式共享媒体索引和缓存。时钟防烧屏采用低亮度、缓慢位移与有限静态元素。

播放与缓存策略

  • Media3 ExoPlayer + CacheDataSource；单进程共享一个 SimpleCache 实例，避免目录锁冲突。
  • 能力探测依次决定 Dolby Vision / 4K / 1080p / 静态图，不能仅根据分辨率或宣传参数判断解码能力。
  • 弱网使用短超时、有限重试和指数退避；起播失败回到静态图，不循环弹错。
  • 缓存上限取“可用空间比例与绝对上限”的较小值；建议从 256MB（低配）/ 1GB（标准）起，允许用户清理。
  • 4K 仅在非计量网络、存储充足和设备能力通过时预取；只有进入环境模式或 Dream 才开始播放，首页不创建播放器。
  • Activity onStop、进入其他 App、系统 Dream 结束立即释放播放器与解码器。
版权闸门

aerial-tv README 明确航拍影片版权归 Apple。生产版本只使用自有、明确授权或许可条款允许的内容与图片源；“能从服务器播放”不等于“可以捆绑、镜像、商用或长期热链”。上线前需完成内容清单、许可凭证与下架替换机制。

11.2 HDMI / 输入源

14.3 安全与隐私基线

  • 不记录通知正文、屏幕内容、观看内容全文、Wi-Fi 密码或账号凭据。
  • 诊断日志默认仅包含 SDK、设备能力、耗时、错误码；包名与内容来源提供脱敏开关。
  • 外部 IntentUri、content Uri、RemoteViews 均视为不可信输入，逐项异常隔离。
  • Partner Bridge 校验 UID + 签名 + 用户授权 + 配额，不能只信任调用方自报 packageName。
  • 上传文件按字节流限额、媒体解码限额、存储配额处理；路径由 Launcher 生成，不采用客户端文件名拼接。
  • 布局导出不含 Token、系统权限和私有 Provider 字段；导入需要用户确认并 schema 校验。
  • 不 Root、不加载隐藏 API、不通过隐蔽保活绕过系统限制；OEM 能力留在签名构建。

15.1 实现策略

  • 首页查询限量：每频道先取 20 条，首屏图片预取 6–8 张，其余滚动加载。
  • 图片按目标像素尺寸解码，统一 Coil/等效图片层；失败占位不重复重组。
  • ViewModel 状态按行拆分，焦点变化不触发所有海报重组。
  • 图标、海报、文件夹合成图使用内存 + 磁盘缓存，包更新使对应缓存失效。
  • Baseline Profile 覆盖冷启动、HOME 恢复、首行滚动和应用页。
  • 低配自动或手动关闭大面积阴影、非必要图片预取和环境媒体自动预载；首页本来就没有实时模糊、视差或视频。
  • 活动 Widget 建议标准版最多 8 个、低配最多 4 个；这是产品预算，不是系统上限。
  • 媒体缓存从 256MB / 1GB 起，受剩余空间约束；存储不足先停预取。
  • Provider 同步去抖、合并与取消，避免连续广播造成全表刷新。
  • R8 / 资源压缩 / 启动耗时日志，禁止在主线程查询 Provider 或解码大图。

15.2 设备等级

DeviceClass 不只按 RAM 判断：综合 API、ActivityManager 内存等级、可用存储、解码能力、历史帧耗时。首次以保守配置启动，运行数据只用于本地效果降级，不做隐蔽设备画像。用户手动选择优先，但“高效果”仍需通过解码与存储闸门。

决策记录（ADR 摘要）

ADR-001
拒绝 Compose for TV 组件库。遵从项目约束，使用 Material 3 手机版控件；代价是自建焦点、方向键和电视布局，独立模块与测试承担复杂度。
ADR-002
不以 WebView 实现桌面。原生 Compose 保证包管理、Widget、焦点、媒体与低配置控制；手机配置页才使用 Web 技术。
ADR-003
Channel 采用多源聚合。系统可见、合作方与 OEM 全量实现同一领域接口，UI 无需感知权限细节，但来源必须可追溯。
ADR-004
Widget 不强行 Compose 化。RemoteViews 必须留在 AppWidgetHostView 内，M3 容器与系统 Provider 的边界不可混淆。
ADR-005
本地缓存优先于实时推荐。桌面首先是启动器；网络失败、Provider 失败不能影响应用入口。

文档结论

本方案可以在 minSdk 23 下交付完整的应用桌面与系统 Widget 宿主；系统 Channel 的覆盖范围必须由 API 版本、ROM 权限和发行版决定。视觉可以完全基于标准 Material 3 手机版控件实现，电视化工作的核心是自建焦点与遥控器层，而不是更换组件库。

TV Launcher 详细设计方案 · 单文件 HTML，无外部脚本、字体或图片依赖 · 建议使用桌面浏览器查看，可通过左侧按钮打印或导出 PDF。
